## `main.cpp`-ში ჩართვა (ლუკას საქმე)

```cpp
// "ფანჯარა B-ზე" (hwnd: window_picker-ით ან ბრძანებით). hello უკვე გვაქვს.
auto vdd = kvm::VirtualDisplay::find();                    // nullopt = დრაივერი არ არის
vdd->attach(hello.screen_w, hello.screen_h, 60, side);     // side = parse_side(cfg.client_side)
const auto where = vdd->rect();                             // where->rect, where->monitor
kvm::WindowMover mover;
mover.send(hwnd, where->rect);                              // Result::Elevated -> "run kvm_host as admin"
kvm::LatestSlot<kvm::CapturedFrame> frames;
auto capture = kvm::ScreenCapture::for_monitor(where->monitor);
capture->start(frames, [] { /* VDD გაქრა: სტრიმი გააჩერე */ });
kvm::VideoSender sender(frames, *video_channel, {.jpeg_quality = cfg.jpeg_quality, .max_fps = cfg.max_fps});
conn->send(proto::StreamStart{.hwnd = reinterpret_cast<std::uint64_t>(hwnd), .title = kvm::to_utf8(title),
                              .width = where->rect.right - where->rect.left,
                              .height = where->rect.bottom - where->rect.top});

// გაჩერება, ზუსტად ამ თანმიმდევრობით:
sender.stop();
capture->stop();
mover.restore(hwnd);     // detach-მდე! თორემ Windows ფანჯარას primary-ზე „დააგდებს“
vdd->detach();
conn->send(proto::StreamStop{.hwnd = ...});
```

- `kvm::display::enable_dpi_awareness()` `main()`-ის დასაწყისში უნდა იყოს. ყველაფერი ფიზიკურ პიქსელებშია.
- WinRT-ისთვის `init_apartment` არ არის საჭირო, `ScreenCapture` MTA-ს თავად ქმნის.
- სანდროს `remote_*`-ის `x_norm`/`y_norm` გადაითვლება `where->rect`-ზე.
- **გამოსვლისას აუცილებლად** შესრულდეს restore და detach, Ctrl+C-ზეც (`SetConsoleCtrlHandler`). თუ host VDD-ით ჩავარდა, აღდგენა შეიძლება `vdd_test.exe`-ით (ის ბოლოს detach-ს აკეთებს) ან Win+P → „PC screen only“-ით.

## შეთავაზება: ფაილების გადატანა გადათრევით

**რა უნდა გუნდს:** ფაილის ან საქაღალდის იკონას A-დან B-ს მხარეს გადაათრევ და ის B-ზე კოპირდება, როგორც Mouse Without Borders-ში. CLAUDE.md-ში „ფაილები“ ჯერ „არ შედის (მერე)“ სიაშია და ამოცანა არავისზეა მიცემული. თემოს T1–T7 დასრულებულია, ამიტომ **თემოს შეუძლია ის აიღოს**, თუ ლუკა თანახმაა.

**ერთი რამ უკვე მუშაობს:** VDD-ის რეჟიმში ფაილის გადატანა B-ზე ნაჩვენებ ფანჯარაში (მაგ. ფოტო Photoshop-ში) გადაცემის გარეშე მუშაობს. ფანჯარა ფიზიკურად A-ზეა, ეს ჩვეულებრივი drag-and-drop-ია A-ზე.

**დიზაინი (v1, მხოლოდ A → B):**
- **ნამდვილი FTP არა:** მას სერვერი, ავტორიზაცია და დამატებითი firewall-ის წესები სჭირდება. ამის ნაცვლად ცალკე TCP არხი, მაგ. **50502**, იგივე framing-ით, რაც ვიდეოს აქვს. header არის JSON, მაგ. `{"type":"file_begin","id","path","size"}`, `{"type":"file_chunk","id","offset"}` + ≤ 1 MB payload, `{"type":"file_end","id"}`. საქაღალდეები ფარდობითი გზებით გადადის.
- **A-ზე გადათრევის დაჭერა:**
  1. როცა დემეტრეს KVM კიდიდან B-ზე გადასვლას აფიქსირებს და მარცხენა ღილაკი დაჭერილია, კურსორის ქვეშ უხილავი ფანჯარა ჩნდება. ის OLE drop target-ია (`RegisterDragDrop`).
  2. ეს ფანჯარა `CF_HDROP`-იდან ფაილების სიას იღებს.
  3. ფაილები 50502-ით B-ზე იგზავნება.
- **B-ზე:** ფაილები ინახება `%USERPROFILE%\Downloads\KVM\`-ში და საქაღალდე იხსნება. v2-ში B-ზე გადათრევა გაგრძელდება (`DoDragDrop`), რომ ფაილი იქ ჩავარდეს, სადაც გინდა.
- **უსაფრთხოება:** B უარყოფს `..`-ს და აბსოლუტურ გზებს, რომ ფაილი სამიზნე საქაღალდის გარეთ არ ჩაიწეროს.
- **ვის ეხება:**
  - ლუკა: ახალი პორტი ან შეტყობინებები, CLAUDE.md-ის ფარგლები;
  - დემეტრე: კიდის გადაკვეთის მოვლენა „ღილაკი დაჭერილია“ ინფორმაციით;
  - თემო: ახალი ფაილები, მაგ. `host_a/file_drop.*`, `client_b/file_receiver.*` და ფაილების არხი. რომელი სად წავა, ლუკამ გადაწყვიტოს.
- **შეფასება:** v1 დაახლოებით 3–4 საათია. v2 (B-ზე გადათრევის გაგრძელება, B → A) დემოს მერე.
