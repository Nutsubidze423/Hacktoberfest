# ლეპტოპის ფანჯრები მეორე მონიტორზე (თემო → ლუკა)

**პრობლემა.** თემოს ლეპტოპიდან გადმოტანილი ფანჯრები ლუკას PC-ზე მხოლოდ **მთავარ მონიტორზე** ჩნდება. desk mode მეორე PC-ის ეკრანად მხოლოდ მის მთავარ მონიტორს იღებს: `hello`-ში მისი ზომა მიდის, overlay და კურსორიც მასზეა მიბმული.

**გამოსავალი, ბრენჩი `temo/desk-monitor`.** tray-ში ჩნდება არჩევანი **„Other PC's windows appear on ▸ Monitor 1 / Monitor 2“** (მხოლოდ ორი ან მეტი მონიტორის დროს). ერთ ჯერზე ერთი მონიტორია.

- **სად ეშვება:** მხოლოდ ლუკას PC-ზე (2 მონიტორი). თემოს ლეპტოპზე **არაფერი იცვლება**.
- **მოქმედი ვერსია და `main` ხელუხლებელია:** ბრენჩი ცალკე საქაღალდეში (git worktree) და ცალკე build-ით ეშვება.
- **დრო:** ~10 წუთი.

## გაშვება

„Developer PowerShell for VS 2022“-ში.

1. **ცალკე საქაღალდე ბრენჩისთვის.** Hacktoberfest-ის საქაღალდიდან. `$main` ინახავს მოქმედი ვერსიის ადგილს:
   ```powershell
   cd C:\path\to\Hacktoberfest
   $main = (Get-Location).Path
   git fetch origin
   git worktree add ..\Hacktoberfest-desk-monitor origin/temo/desk-monitor
   ```
2. **Build.** საკუთარ `build` საქაღალდეში, მოქმედ exe-ებს არ ცვლის:
   ```powershell
   cd ..\Hacktoberfest-desk-monitor
   cmake --preset x64-release
   cmake --build --preset x64-release
   ```
3. **მოქმედი Sarke-ის დახურვა.** ერთ PC-ზე ორი ერთად ვერ იმუშავებს. tray → **Quit Sarke**, ან:
   ```powershell
   & "$main\build\x64-release\tools\sarke.exe" --quit
   ```
   ინსტალერით დაყენებული: `& "$env:ProgramFiles\Sarke\sarke.exe" --quit`
4. **ახალი ვერსია, იმავე `config.json`-ით.** განლაგება და დამახსოვრებული PC-ები უცვლელი რჩება. ახალი ვერსია მხოლოდ `desk_monitor` ველს ამატებს, რომელსაც ძველი უბრალოდ ვერ ხედავს:
   ```powershell
   .\build\x64-release\tools\sarke.exe --config "$main\config.json"
   ```
   ინსტალერით დაყენებულის config: `--config "$env:LOCALAPPDATA\Sarke\config.json"`
5. **მონიტორის არჩევა.** tray → **Other PC's windows appear on** → **Monitor 2**. ნომრები ემთხვევა Windows-ის Settings → Display-ს. Sarke თავისით გადაიტვირთება.
6. **დაკავშირება.** თემოს ლეპტოპი ჩვეულებრივად უკავშირდება. ლეპტოპზე ფანჯარა კიდეზე გადაათრიე: Monitor 2-ზე უნდა გამოჩნდეს.

## რა შევამოწმოთ

- [ ] ლეპტოპის ფანჯარა Monitor 2-ზე ჩნდება, იმავე ადგილას, სადაც ლეპტოპზე დატოვე.
- [ ] ლეპტოპის კურსორი კიდეზე გადასვლისას Monitor 2-ზე გადმოდის და ბოლომდე მიდის, კუთხეებშიც.
- [ ] ლუკას მაუსით ამ ფანჯარაზე კლიკი, სქროლი და ტექსტის აკრეფა მუშაობს.
- [ ] Monitor 2-ის ცარიელ ადგილას, ფანჯრის გარეთ კლიკი ლუკას desktop-ს ეკუთვნის.
- [ ] მენიუდან Monitor 1-ზე დაბრუნება: ფანჯრები ისევ მთავარზე ჩნდება.

## უკან დაბრუნება

ახალი დახურე და მოქმედი ჩართე. მონიშნული მონიტორი config-ში რჩება, მაგრამ ძველი ვერსია მას ვერ ხედავს და ფანჯრები ისევ მთავარ მონიტორზე ჩნდება.

```powershell
.\build\x64-release\tools\sarke.exe --quit
& "$main\build\x64-release\tools\sarke.exe"
```

ტესტის მერე ცალკე საქაღალდის წაშლა (მთავარი საქაღალდიდან): `git worktree remove ..\Hacktoberfest-desk-monitor`

## რა შეიცვალა კოდში

- `config.json` → `"desk_monitor"`: მონიტორის სახელი, მაგ. `\\.\DISPLAY2`. `""` = მთავარი.
- `display::desk_monitor()` (`dpi.*`): უცნობი სახელის ან VDD-ის შემთხვევაში მთავარ მონიტორს აბრუნებს.
- `hello` ორივე `main.cpp`-ში: არჩეული მონიტორის ზომა და მასშტაბი, ამიტომ ლეპტოპის VDD მის ზომაზე დგება.
- `DeskView` მასზე ხატავს. `InputInject`-ში desk mode-ის კურსორიც მასზე გადადის.
- tray ქვემენიუ (`launcher.cpp`); ტესტი `dpi_test`-ში.
- **ლუკას ფაილები:** ორივე `main.cpp` და `config.*`.

**ცნობილი შეზღუდვა:** ერთ ჯერზე ერთი მონიტორი. ორივე ერთად, ნამდვილი მესამე და მეოთხე ეკრანივით, თითო მონიტორზე ცალკე ვირტუალურ ეკრანს მოითხოვს. ეს შემდეგი ეტაპია.

შედეგი თემოს მიწერე: თუ ყველა პუნქტი გავიდა, ბრენჩი `main`-ში შევა.
