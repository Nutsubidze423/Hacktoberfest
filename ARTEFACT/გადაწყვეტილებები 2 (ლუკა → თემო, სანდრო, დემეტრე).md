# გადაწყვეტილებები 2: ყველაფერი ორივე მიმართულებით (A ⇄ B), ახლავე

Claude, ეს ფაილი თემოს, სანდროს და დემეტრეს სესიებისთვისაა.

**ლუკას გადაწყვეტილება:** დემოში **ყველა ფუნქცია ორივე მიმართულებით** მუშაობს:
- **KVM:** A-ს მაუსი და კლავიატურა B-ზე, და **B-ს მაუსი და კლავიატურა A-ზე**;
- **ფანჯარა:** A-ს ფანჯარა B-ზე, და **B-ს ფანჯარა A-ზე**;
- **ფაილები:** გადათრევით A → B და **B → A**.

ჯერ ჩამოტვირთე `main`, მერე იპოვე შენი დეველოპერის სექცია. **ერთი დავალება = ერთი ბრენჩი**. სხვის ფაილებს ნუ შეეხები.

## რა შეიცვალა main-ში (ლუკა, ამ commit-ით)

- **`protocol.h` → v2.** შეტყობინებების ველები არ შეცვლილა, შეიცვალა მიმართულებები. ძველ build-თან კავშირი არ შედგება, ამიტომ **ტესტის წინ ორივე მხარე ერთი commit-იდან ააწყვეთ**.
  - `hello`: ორივე მიმართულებით. B აგზავნის, A ამოწმებს და თავისას უპასუხებს. ასე B-მ A-ს ეკრანის ზომა იცის და თავის VDD-ს მის ზომაზე აყენებს.
  - `focus_enter` / `focus_leave` / `mouse_move` / `mouse_button` / `mouse_wheel` / `key` (KVM): **„owner“** არის ის მხარე, ვისი ფიზიკური მაუსიც კიდეს გადაკვეთს. მისი შეტყობინებები controlled მხარეს მიდის. `focus_leave`-ს ორივე აგზავნის.
  - `stream_start` / `stream_stop` / `remote_*`: **window owner** (სადაც აპი მუშაობს) → viewer, და პირიქით. `stream_stop` viewer-იდან owner-ზე ნიშნავს „დამიბრუნე“.
- **CMake:** `kvm_host` და `kvm_client` ორივე **ორივე** ბიბლიოთეკას ლინკავს (`kvm_host_lib` + `kvm_client_lib`). შედეგად თემოს capture/`WindowShare` B-ზეც არის, სანდროს viewer A-ზეც, დემეტრეს `InputCapture`/`InputInject` ორივეგან. `kvm_client_lib`-ს `d2d1 dwrite windowscodecs` დაემატა სანდროს viewer-ისთვის.
- **firewall:** 50500–**50502**, და `1_allow_firewall.cmd` **ორივე** კომპიუტერზე უნდა გაეშვას, რადგან ფაილები ორივე მიმართულებით მოდის.

ფაილების მდებარეობა (`host_a/` თუ `client_b/`) აღარ ნიშნავს „მხოლოდ A“-ს ან „მხოლოდ B“-ს. ის მხოლოდ მფლობელს აჩვენებს. **ახალი, ორივე მხარისთვის საჭირო კოდი** უბრალოდ თქვენს ჩვეულ საქაღალდეში დაწერეთ, და ორივე exe მას მიიღებს.

## სანდრო

### S1. receiver ლუკას ვიდეოს არხზე (**დამბლოკავია, პირველ რიგში**)
- `client_b/video_receiver.*`-დან წაშალე `namespace kvm::video_wire` მთლიანად.
- ნაცვლად `#include "kvm/video.h"`. receiver-ს `kvm::net::FrameChannel&` გადაეცით, საკუთარი კავშირის გახსნის ნაცვლად:
  ```cpp
  // გადაეცემა გარედან (ლუკას main.cpp ქმნის: B-ზე connect_video, A-ზე VideoServer::accept)
  while (auto frame = channel.recv_frame()) { ... }   // frame->header (FrameHeader), frame->payload (JPEG)
  channel.close();                                    // სხვა thread-იდან: recv_frame-ს აღვიძებს
  ```
  **რატომ გარედან:** ორმხრივი ვიდეოსთვის ერთი TCP არხი ორივე მიმართულებით მუშაობს. A-ს ფანჯრის ფრეიმები A → B მიდის, B-ს ფანჯრისა B → A, ორივე იმავე `FrameChannel`-ზე. `send_frame` thread-safe-ია, `recv_frame` მხოლოდ ერთი thread-იდან იძახება. ამიტომ კავშირს `main.cpp` ფლობს, receiver კი მხოლოდ კითხულობს. reconnect-იც `main.cpp`-შია.
- latency: `t_capture_us` owner-ის საათითაა. მიმღებ მხარეს ასე გადაიყვანება: `conn.peer_to_local_us(t)`. `set_clock_offset_us()` დატოვე, ლუკა მიაწვდის.
- ტესტი: `kvm_host.exe --no-kvm --test-video`. ფრეიმებს `codec = "test"` აქვთ (შემთხვევითი ბაიტები), ამიტომ გამოტოვე ან ჩვენების გარეშე დაითვალე. JPEG-ით ტესტისთვის: შენი `fake_streamer`, `video.h`-ზე გადაყვანილი.

### S2. `main`-ში ატვირთვა
- ბრენჩი `main`-ზე rebase გააკეთე. `docs/PLAN.md`-ში კონფლიქტის შემთხვევაში ორივე მხარე დატოვე. ატვირთე.
- CMakeLists-ს ნუ შეცვლი. `d2d1 dwrite windowscodecs` უკვე დამატებულია. თუ სხვა ბიბლიოთეკა დაგჭირდა, ლუკას უთხარი.

### S3. viewer-ის ინფუთი → window owner (ორივე მხარეს)
- `WM_MOUSEMOVE` → `remote_mouse_move`, `WM_*BUTTON*` → `mouse_button` (+ `x_norm`/`y_norm`), `WM_MOUSEWHEEL`/`WM_MOUSEHWHEEL` → `mouse_wheel`, `WM_KEYDOWN/UP` + `WM_SYSKEY*` → `key` (scan `(lParam >> 16) & 0xFF`, extended `lParam & (1 << 24)`).
- `x_norm`/`y_norm` გამოსახულების მიმართ ითვლება (aspect ratio-ს ზოლების გარეშე). ზოლებზე კლიკი არ იგზავნება.
- გაგზავნა callback-ით: `std::function<bool(const proto::Message&)>`. ლუკა მას `conn.send_json`-ს მიუერთებს.
- `SetCapture` ღილაკზე დაჭერისას. viewer-ის დახურვა ან „დაბრუნების“ ღილაკი → `StreamStop{.hwnd}`.
- viewer-ზე მოსული მოვლენა შეიძლება დემეტრეს KVM-იდან იყოს (`dwExtraInfo == kInjectedMarker`): მაგალითად, A-ს მაუსი, რომელიც B-ზეა გადასული. ესეც ჩვეულებრივ უნდა გაიგზავნოს.

## თემო

### T8. `remote_input.*` (owner-ის მხარე, ორივე exe-ში)
- `remote_mouse_move` / `mouse_button` / `mouse_wheel` / `key` → `share->monitor_rect()` → `SendInput` (`MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK`). კლავიშებისთვის დემეტრეს `kvm::input::*`.
- **ყველა** ჩასმულ მოვლენას `dwExtraInfo = kInjectedMarker` სჭირდება, თორემ დემეტრეს hooks მას ფიზიკურ ინფუთად ჩათვლის.
- interface: `bool handle(const proto::Message&)`. `true` ნიშნავს, რომ შეტყობინება ამოიცნო.
- `WindowShare` B-ზეც უნდა მუშაობდეს: VDD-ის ზომა = **მეორე მხარის** `hello` (`screen_w/h`). B-ზე ეს A-ს პასუხის `hello`-ა.

### T9. ფაილები A ⇄ B
- **ფაილები (ფლობს თემო):** `common/include/kvm/file_transfer.h` + `common/src/file_transfer.cpp` (არხი 50502, გაგზავნა და მიღება, სიმეტრიულად: A უსმენს, B უკავშირდება, მერე ორივე ორივე მიმართულებით აგზავნის). `common/include/kvm/file_drop.h` + `common/src/file_drop.cpp` (უხილავი OLE drop target). `common/`-ში ეს **თემოს** ფაილებია.
- socket-ის დამხმარე ფუნქციები: `common/src/socket_util.h` (`listen_on`, `accept_on`, `connect_to`, `send_all`, `recv_exact`). **არ შეცვალო**. თუ რამე აკლია, ლუკას უთხარი.
- wire: `[u32 header_len][u32 payload_len][header JSON][payload]`. header-ები: `file_begin {id, path, size}`, `file_chunk {id, offset}` + ≤ 1 MB payload, `file_end {id}`, `transfer_end {count}`. path ფარდობითია, `/`-ით.
- **უსაფრთხოება:** უარყავი `..`, აბსოლუტური გზა, დისკის ასო და `\\?\`. ჩაწერა მხოლოდ `Downloads\KVM\`-ში. თუ ფაილი უკვე არსებობს, დაემატოს ` (2)`.
- გადათრევის მომენტს დემეტრეს KVM იძლევა (D1). interface მასთან ერთად შეათანხმე.

## დემეტრე

### D0. KVM B → A
შენ უკვე აკეთებ. `InputCapture` B-ზე და `InputInject` A-ზე. ორივე exe ახლა ორივე ბიბლიოთეკას ლინკავს, ამიტომ კლასები ორივეგან ხელმისაწვდომია. კიდე ორივე მხარისთვის `client_side`-იდან გამოითვლება: A-ზე `client_side`-ის მხარე, B-ზე საპირისპირო. `main.cpp`-ში ორივე მხარეს ორივე კლასის ჩართვაზე ლუკას დაელაპარაკე, ან თავად შეაერთე, როგორც `5c1f3e3`-ში, ოღონდ ლუკასთან შეთანხმებით.

### D1. ფაილის გადათრევა კიდეზე (T9-ისთვის, თემოსთან ერთად)
- ახლა KVM ღილაკდაჭერილ გადასვლას კიდეზე ბლოკავს. ეს ჩვეულებრივი drag-ისთვის რჩება.
- როცა კურსორი owner-ისკენ მიმართულ კიდეს ეხება **მარცხენა ღილაკდაჭერილი**, callback-ით შეატყობინე (`on_drag_at_edge(y_norm)`), რომ თემოს `file_drop` catcher ფანჯარა გამოაჩინოს. drop-ის ან ~1.5 წმ-ის შემდეგ ჩვეულებრივი გადასვლა გაგრძელდეს. ორივე მიმართულებით.

### D2. VDD და KVM-ის კიდე
VDD ჩართვისას (`client_side`-ის მხარე) გარე კიდე VDD-ის კიდეა. შეამოწმე, რომ `refresh_monitors` `WM_DISPLAYCHANGE`-ზე სწორად მუშაობს და გადასვლა A → VDD → კიდე → B ბუნებრივია. თუ დემოსთვის მოუხერხებელია, ლუკას უთხარი. ალტერნატივაა VDD-ის საპირისპირო მხარეს დადგმა.
